# RetailHero — A/B-анализ и uplift-таргетинг

**Бизнес-задача:** рекламные SMS стоят денег. Нужно (1) оценить, повышает ли коммуникация вероятность покупки, и (2) определить, можно ли получить больше **дополнительных покупок при том же количестве контактов**, используя uplift-модель.

> **Тип проекта:** портфолио-анализ открытых исторических данных X5 RetailHero. Исходный A/B-тест **уже был проведён до исследования**; автор не запускал рассылку. Следующий A/B-тест двух стратегий разработан **как проект**, но не запускался.

## Перекрёстная проверка: 3-fold out-of-fold

**Последняя ретроспективная проверка (30.10.2026), 200 039 клиентов.** Каждый прогноз для проверяемого клиента построен моделью, не обучавшейся на его результате.

| Метрика | Итог |
|---|---:|
| Случайный таргетинг: средний uplift | **+3,323 п.п.** |
| T-learner с RFM: uplift топ-10% | **+6,842 п.п.** |
| Преимущество на контакт | **+3,519 п.п. / +105,9%** |
| Условный парный bootstrap 95% ДИ преимущества | **[+2,248; +4,803] п.п.** |
| Преимущество по трём фолдам | **+3,095 / +3,608 / +3,927 п.п.** |
| 6 000 SMS: потенциальные дополнительные покупки | **~411 против ~199**, разница ~211 |

Сравнили стратегию с простыми правилами частоты, суммы и давности покупок: все эти эвристики уступили T-learner в агрегированной исторической оценке. **Это не новый A/B-тест и не независимая внешняя выборка:** исходные данные уже использовались для выбора модели. Bootstrap не учитывает переобучение модели, адаптивный выбор и перенос на новых клиентов.

**Происхождение результатов.** В исходном сохранённом выполнении ноутбука `final_stats.csv` не загружался: модель использовала только возраст и пол, uplift топ-10% = **4,922 п. п.**. Число **8,36 п. п.** из старого README не было воспроизведено и исключено. **30 октября 2026** расширенная модель с `BUILD_RFM = True` была выполнена пользователем в Google Colab: выполненный ноутбук с сохранёнными выходными ячейками подтверждает **+3,483 п. п.** преимущества над случайной стратегией, bootstrap 95% ДИ **[+1,129; +5,922]**. Для повторения расширенного результата необходимо запускать ноутбук с включённым `BUILD_RFM`. В отдельном [выполненном RFM-ноутбуке](notebooks/RetailHero_AB_Uplift_RFM_executed.ipynb) сохранены полные результаты этого запуска, включая таблицы и графики.

Дизайн исходной кампании проверить полностью невозможно: в открытом датасете есть `treatment_flg` и `target`, но нет полной документации по рандомизации, доставке сообщений, стоимости контакта и марже.

## Что это означает для бизнеса

При одинаковом бюджете на **6 000 SMS** и переносе точечных оценок из исторического holdout:

| Стратегия | Оценка дополнительных покупок | Разница к случайной |
|---|---:|---:|
| Случайный выбор | **≈199** | — |
| Топ-10% по базовой модели | **≈295** | **+96** (95% ДИ от **−45** до **+234**) |
| Топ-10% по RFM-модели | **≈408** | **+209** (95% ДИ от **+68** до **+355**) |

Для **расширенной модели** точечная оценка превышения uplift над случайным выбором — **+3,483 п. п.** на контакт, 95% bootstrap ДИ **[+1,129; +5,922]**. Оценочное увеличение дополнительных покупок на контакт — **+104,5%**. При одинаковой цене SMS это подразумевает условное снижение затрат на одну дополнительную покупку примерно **на 51,1%** (точечная оценка).

**Что статистически установлено:** для фиксированной RFM-модели на этом историческом holdout bootstrap ДИ положителен. **Что НЕ установлено:** финансовая экономия X5, превосходство новой политики в реальной кампании и полностью независимая валидация. После просмотра результатов базовой модели на том же holdout мы расширили набор признаков и заново оценили результат; поэтому CI **не учитывает выбор модели по просмотренным результатам**, переобучение или перенос на новую аудиторию. Нужен новый эксперимент.

**Иллюстративная экономика:** при условной марже **200 ₽** с дополнительной покупки точечное преимущество RFM-политики на 6 000 SMS = **≈41 666 ₽** до издержек на разработку и эксплуатацию модели, при неизменной цене контакта. Это **не фактически полученная прибыль**, реальные маржа, бонусы и стоимость SMS не известны.

## Временная логика данных

По [описанию X5 RetailHero](https://ods.ai/competitions/x5-retailhero-uplift-modeling/data) `purchases.csv` содержит **историю до коммуникации**, а в `uplift_train.csv` лежат `treatment_flg` (получил ли клиент рекламное сообщение) и `target` (купил ли после сообщения). В `uplift_train.csv` нет персонального времени SMS. Таким образом, анализ A/B сравнивает группы **после кампании**, а модель может пользоваться только признаками, известными **до неё**.

Дату последней покупки из истории можно использовать для RFM-признака. Поскольку точная дата SMS не предоставлена, давность последней покупки рассчитывается **от конца исторического набора**, а не от несуществующей даты SMS.

## Как оценивали

1. **Исторический A/B-тест:** сравнили доли покупок, проверили SRM и баланс доступных признаков, построили доверительный интервал и провели z-тест.
2. **Гетерогенность:** исследовали возрастные/гендерные сегменты и тесты взаимодействий; статистическая значимость отдельных сегментов не доказывает различие их эффектов.
3. **Uplift:** T-learner из двух `HistGradientBoostingClassifier`, обученных на разных экспериментальных группах. Оценили эффект в топ-долях по скору на независимых от обучения 30% клиентов.
4. **Бизнес-сценарий:** сопоставили две стратегии при одинаковом числе SMS.
5. **Проверка устойчивости:** рассчитали стратифицированный bootstrap ДИ для двух вариантов. У базовой модели он содержит ноль, у RFM — положителен на фиксированной исторической holdout-выборке. Ограничения повторного просмотра holdout и внешней проверки отдельно отмечены.

## Следующий A/B-тест (дизайн, без запуска)

Самостоятельно спроектирован эксперимент для оценки **не эффекта SMS как таковых**, а **преимущества новой политики выбора получателей**:

- рандомизировать новых клиентов 1:1 между политиками;
- A: случайно направлять SMS 10% своей группы; B: направлять SMS 10% своей группы с максимальным прогнозным uplift;
- измерять конверсию **всех** назначенных в каждую политику клиентов, а не только получивших SMS;
- заранее определить MDE, мощность, правила остановки и guardrail-метрики.

При прежней базовой оценке ожидаемая разница между политиками составляла **≈0,16 п. п.** по всем клиентам (ориентир **~1,5 млн** на группу). С RFM-моделью точечная оценка увеличилась до **≈0,348 п. п.** по всем клиентам. При тех же предположениях двустороннего α=5% и мощности 80% ориентир — **~310 тыс. клиентов на группу**. Это грубые плановые оценки, основанные на адаптивно выбранных исторических результатах, а не согласованный размер будущего эксперимента.

## Воспроизведение

1. Открыть ноутбук в Google Colab и выполнить ячейки по порядку. Основные открытые данные скачиваются с Hugging Face.
2. **Базовый воспроизводимый вариант:** без `final_stats.csv` используются только демографические признаки, как в сохранённом запуске.
3. **Опционально: RFM-обогащение.** В ноутбуке установить `BUILD_RFM = True`, выполнить ячейки с начала. Это скачает исходный `purchases.csv.gz` (~609 МБ), установит `duckdb`, создаст агрегаты из чеков в `data/final_stats.csv` и подключит 8 признаков истории. На полный проход потребуется место для временных файлов и достаточная оперативная память. **Результат расширенной модели получен в Colab и приведён выше; для воспроизведения необходимо включить данный режим.**
4. **Альтернативно:** при наличии предварительно агрегированных исторических данных поместить `final_stats.csv` с колонками `client_id`, `count`, `sum` в рабочую папку Colab; код подключит дополнительные признаки, но результаты будут другими и требуют повторной валидации.
5. Сырые покупки при необходимости подготовить командой:

   ```bash
   pip install duckdb
   python scripts/build_rfm_features.py --input data/purchases.csv.gz --output data/final_stats.csv
   ```

**Ограничения:** исходный датасет предоставлен как предкампанийная история плюс посткампанийный бинарный исход; неизвестна точная дата SMS. Bootstrap по RFM дал 95% ДИ [+1,129; +5,922] п. п. при 3000 повторах (seed=42). Он отражает неопределённость при фиксированном ранжировании в историческом holdout, **но не охватывает адаптивный выбор модели по тому же holdout**, повторное обучение и сдвиг аудитории. Результат новой стратегии не проверен в отдельном проспективном A/B-тесте.

**Датасеты:** [ODS RetailHero](https://ods.ai/competitions/x5-retailhero-uplift-modeling/data) · [Hugging Face](https://huggingface.co/datasets/pytorch-lifestream/retailhero-uplift/tree/main/data).
