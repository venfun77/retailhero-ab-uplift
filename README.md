# RetailHero — A/B-анализ и uplift-таргетинг

**Бизнес-задача:** рекламные SMS стоят денег. Нужно (1) оценить, повышает ли коммуникация вероятность покупки, и (2) определить, можно ли получить больше **дополнительных покупок при том же количестве контактов**, используя uplift-модель.

> **Тип проекта:** портфолио-анализ открытых исторических данных X5 RetailHero. Исходный A/B-тест **уже был проведён до исследования**; автор не запускал рассылку. Следующий A/B-тест двух стратегий разработан **как проект**, но не запускался.

## Результаты воспроизводимого запуска

| Метрика | Результат |
|---|---:|
| Клиентов в исходном A/B-тесте | **200 039** |
| Конверсия без / с коммуникацией | **60,33% / 63,65%** |
| Средний эффект SMS | **+3,32 п. п.** |
| 95% ДИ среднего эффекта | **[+2,90; +3,75] п. п.** |
| p-value z-теста двух долей | **6,62 × 10⁻⁵³** |
| Uplift в топ-10% по модели, на holdout | **+4,922 п. п.** |
| Uplift по всему holdout | **+3,321 п. п.** |
| Относительный прирост дополнительных конверсий на контакт, точечная оценка | **около +48%** |

**Почему не +8,36 п. п.?** Это число ранее было указано в README, но **не воспроизводится в сохранённом запуске** ноутбука. В опубликованном выполнении не был загружен `final_stats.csv`: модель использовала только возраст и пол. Поэтому здесь приведено значение **+4,922 п. п.** из фактического вывода ячейки. Если появится воспроизводимый запуск с историей покупок, сравнение можно будет обновить отдельно.

Дизайн исходной кампании проверить полностью невозможно: в открытом датасете есть `treatment_flg` и `target`, но нет полной документации по рандомизации, доставке сообщений, стоимости контакта и марже.

## Что это означает для бизнеса

При одинаковом бюджете на **6 000 контактов**, используя точечные оценки из holdout:

| Политика выбора получателей | Оценка дополнительных покупок |
|---|---:|
| Случайный выбор (средний uplift 3,321 п. п.) | **~199** |
| Топ-10% по uplift-модели (4,922 п. п.) | **~295** |
| **Разница** | **~96** |

Относительное преимущество составляет **около +48% на контакт**; расчётная стоимость одной дополнительной покупки при одинаковой цене SMS — **примерно на 32,5% меньше**. Это *не реальная экономия X5* и *не результат нового эксперимента*: точечная оценка по старым данным без переноса неопределённости в это сравнение.

**Иллюстративный финансовый сценарий:** если маржинальный вклад одной дополнительной покупки равен 200 ₽, разница составит около **19 200 ₽** на 6 000 контактов до затрат на разработку/поддержку модели. Стоимость SMS, бонусы и реальная маржа неизвестны; значение 200 ₽ — только предположение.

## Как оценивали

1. **Исторический A/B-тест:** сравнили доли покупок, проверили SRM и баланс доступных признаков, построили доверительный интервал и провели z-тест.
2. **Гетерогенность:** исследовали возрастные/гендерные сегменты и тесты взаимодействий; статистическая значимость отдельных сегментов не доказывает различие их эффектов.
3. **Uplift:** T-learner из двух `HistGradientBoostingClassifier`, обученных на разных экспериментальных группах. Оценили эффект в топ-долях по скору на независимых от обучения 30% клиентов.
4. **Бизнес-сценарий:** сопоставили две стратегии при одинаковом числе SMS и обозначили ограничения финансовой интерпретации.

## Следующий A/B-тест (дизайн, без запуска)

Самостоятельно спроектирован эксперимент для оценки **не эффекта SMS как таковых**, а **преимущества новой политики выбора получателей**:

- рандомизировать новых клиентов 1:1 между политиками;
- A: случайно направлять SMS 10% своей группы; B: направлять SMS 10% своей группы с максимальным прогнозным uplift;
- измерять конверсию **всех** назначенных в каждую политику клиентов, а не только получивших SMS;
- заранее определить MDE, мощность, правила остановки и guardrail-метрики.

При исторической точечной оценке разница на **всех клиентах** может оказаться всего ~**0,16 п. п.**, что потребует весьма большой аудитории (ориентировочно **~1,5 млн клиентов на группу** для двустороннего α=5%, мощности 80% и выбранных предположений).

## Воспроизведение

1. Открыть ноутбук в Google Colab и выполнить ячейки по порядку. Основные открытые данные скачиваются с Hugging Face.
2. **Базовый воспроизводимый вариант:** без `final_stats.csv` используются только демографические признаки, как в сохранённом запуске.
3. **Расширенный вариант:** при наличии предварительно агрегированных исторических данных поместить `final_stats.csv` с колонками `client_id`, `count`, `sum` в рабочую папку Colab; код подключит дополнительные признаки, но результаты будут другими и требуют повторной валидации.
4. Сырые покупки при необходимости подготовить командой:

   ```bash
   python scripts/build_purchase_features.py --input data/purchases.csv.gz --output data/final_stats.csv
   ```

**Ограничения:** без новой кампании нельзя подтвердить эффект смены стратегии. Сохранённый uplift — точечная оценка на holdout без предъявленного ДИ именно для преимущества модели; также возможен сдвиг аудитории и недостаточная гибкость демографических признаков.
